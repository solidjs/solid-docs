`<Loading on>` changed but its data is also read outside the boundary and holds the frame: the fallback can never be seen.

## What you saw

- **Kind:** `async`
- **Severity:** `warn` (code that works but is structurally wrong or expensive)

The console report opens with `[LOADING_ON_OUTSIDE_HOLD]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "LOADING_ON_OUTSIDE_HOLD"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

`on` re-armed a Loading boundary, but a source it is waiting on is also read outside the boundary and holds the frame.
The frame waits for that same source, so the fallback cannot appear.

## How to fix it

Move the outside read under the boundary.
If the fallback should appear immediately beside the held frame, use a `latest()` read in `on`.
