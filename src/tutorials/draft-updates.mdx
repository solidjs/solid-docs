# Updating drafts

Store setters provide the draft you mutate. Arrays can be pushed, spliced, and traversed within the callback; nested fields can be assigned directly.

```js
setTodos((draft) => {
  const todo = draft.find((todo) => todo.id === id);
  if (todo) todo.completed = !todo.completed;
});
```

These mutations describe one staged update. They do not grant permission to mutate the read-only store elsewhere. Like signal writes, the results become visible when the batch commits.

**Try it:** implement **Complete all** with a loop that sets each draft todo's `completed` field. Implement **Clear completed** by splicing completed entries. Iterate backward when deleting so adjacent matching entries are not skipped. Add several todos, complete some or all of them, and clear the completed entries.

The draft groups these related writes into one update. Use stable item identities so unchanged rows keep their DOM and owned state.
