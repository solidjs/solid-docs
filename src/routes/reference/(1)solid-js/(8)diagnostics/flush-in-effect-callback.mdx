`flush()` from an effect callback (no-op; the drain is already running).

- **Severity:** `warn` (code that works but is structurally wrong or expensive)

[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

`flush()` was called inside an effect callback, where it is a no-op (the flush running effects is already in progress).
Writes made there are handled in the same flush's continuation.

## How to fix it

If you truly need a drain afterwards, defer it: `queueMicrotask(() => flush())`.
Usually the right fix is deleting the call.
