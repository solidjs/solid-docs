# Lists by position

Sometimes each position should retain its DOM while the value at that position changes. Solid 2 expresses this with `For keyed={false}`.

```jsx
<For each={cats()} keyed={false}>
  {(cat, index) => (
    <li>
      {index + 1}: {cat().name}
    </li>
  )}
</For>
```

This callback has an item getter and a stable numeric index. That differs from the default identity mode, where the item is raw and the index is a getter. Use a literal keying mode so the callback's meaning stays clear.

**Try it:** render the cats with position mapping instead of the hard-coded list item. Call `cat()` when reading its fields and use `index` without calling it. This is useful for fixed slots whose values change.

Type a note in the first row, then use **Rotate cats**. Position mapping keeps that row's DOM and note in the first position while its cat changes. Compare this with the identity-mapped list in the previous lesson.
