Reactive write/invalidation inside component/computation.

## What you saw

- **Kind:** `write`
- **Severity:** `error` (broken behavior)

The console report opens with `[REACTIVE_WRITE_IN_OWNED_SCOPE]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "REACTIVE_WRITE_IN_OWNED_SCOPE"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

A signal/store write (or `refresh()`) executed during an owned scope — a component body or a computation.
Pure scopes must not cause state changes.

## How to fix it

Move the write to an event handler or effect phase.
If the write is genuinely intentional initialization, pass the `ownedWrite` option on the setter call.
