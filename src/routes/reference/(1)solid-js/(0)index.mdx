`solid-js` is the reactive core.
It has no knowledge of the DOM; the same primitives run in the browser, on the server, and in tests.
Rendering functions live in [`@solidjs/web`](/reference/solid-web).

Every export here is imported from `"solid-js"`:

```ts
import { createSignal, createMemo, createStore, Show, For } from "solid-js";
```

## Reactivity

Values that change over time and the computations that follow them.
[Reactivity](/concepts/reactivity) explains the model.

- [`createSignal`](/reference/solid-js/reactivity/create-signal) creates a readable, writable value.
- [`createMemo`](/reference/solid-js/reactivity/create-memo) derives a cached value from other reactive reads, including async ones.
- [`createEffect`](/reference/solid-js/reactivity/create-effect) runs side effects after tracked values change.
- [`createOptimistic`](/reference/solid-js/reactivity/create-optimistic) creates a signal whose writes inside an action are tentative.
- [`isPending`](/reference/solid-js/reactivity/is-pending) reports that a new answer is on the way; [`latest`](/reference/solid-js/reactivity/latest) reads it early.
- [`untrack`](/reference/solid-js/reactivity/untrack) reads without subscribing; [`flush`](/reference/solid-js/reactivity/flush) drains the update queue now.

## Stores

Nested reactive state with per-property tracking.
[Stores](/concepts/stores) covers drafts, projections, and optimistic stores.

- [`createStore`](/reference/solid-js/stores/create-store) wraps an object or array; the setter receives a draft.
- [`createProjection`](/reference/solid-js/stores/create-projection) derives a read-only store from other reactive reads.
- [`createOptimisticStore`](/reference/solid-js/stores/create-optimistic-store) is the store form of `createOptimistic`.
- [`reconcile`](/reference/solid-js/stores/reconcile) merges new data into a store by key.
- [`merge`](/reference/solid-js/stores/merge) and [`omit`](/reference/solid-js/stores/omit) combine and split props without losing reactivity.

## Lifecycle and actions

Coordinating async work and the moments around it.
[Async reactivity](/concepts/async-reactivity) is the concept page.

- [`action`](/reference/solid-js/lifecycle-actions/action) runs a mutation whose writes commit together.
- [`onSettled`](/reference/solid-js/lifecycle-actions/on-settled) runs once after the current owner's pending work has finished, and can return a cleanup.
- [`refresh`](/reference/solid-js/lifecycle-actions/refresh) re-asks an async source; [`affects`](/reference/solid-js/lifecycle-actions/affects) marks values as pending while it does.
- [`until`](/reference/solid-js/lifecycle-actions/until) awaits a reactive condition.

## Components and context

- [`createContext`](/reference/solid-js/components-context/create-context) and [`useContext`](/reference/solid-js/components-context/use-context) share a value with a subtree.
- [`children`](/reference/solid-js/components-context/children) resolves `props.children` for inspection.
- [`lazy`](/reference/solid-js/components-context/lazy) code-splits a component.
- [`createUniqueId`](/reference/solid-js/components-context/create-unique-id) generates ids that match between server and client.

## Flow components

Built-in components for conditions, lists, and boundaries.
[Components and JSX](/concepts/components-and-jsx) and [Boundaries](/concepts/boundaries) show them in use.

- [`Show`](/reference/solid-js/components-jsx/show) renders content when a condition holds.
- [`Switch` and `Match`](/reference/solid-js/components-jsx/switch-and-match) pick the first matching branch.
- [`For`](/reference/solid-js/components-jsx/for) renders a row per array item; [`Repeat`](/reference/solid-js/components-jsx/repeat) renders a row per index.
- [`Loading`](/reference/solid-js/components-jsx/loading) shows a fallback while async reads have no value.
- [`Errored`](/reference/solid-js/components-jsx/errored) renders a fallback when the subtree throws.
- [`Reveal`](/reference/solid-js/components-jsx/reveal) orders how sibling `Loading` boundaries appear.

## Advanced

Owner introspection, specialized effects, store internals, boundary primitives, manual hydration, interop, and development hooks.
These pages support libraries and tooling; application code rarely needs them.

- [`createRoot`](/reference/solid-js/advanced/owner-introspection/create-root), [`getOwner`](/reference/solid-js/advanced/owner-introspection/get-owner), and [`runWithOwner`](/reference/solid-js/advanced/owner-introspection/run-with-owner) manage reactive scopes by hand.
- [`createRenderEffect`](/reference/solid-js/advanced/specialized-reactivity/create-render-effect) and [`onCleanup`](/reference/solid-js/advanced/specialized-reactivity/on-cleanup) serve renderers and custom primitives.
- [`createLoadingBoundary`](/reference/solid-js/advanced/jsx-component-primitives/create-loading-boundary) and [`createErrorBoundary`](/reference/solid-js/advanced/jsx-component-primitives/create-error-boundary) back the flow components.
- [`DEV`](/reference/solid-js/advanced/diagnostics-dev-hooks/dev) exposes the development diagnostics that [Debugging reactivity](/guides/debugging-reactivity) reads.
