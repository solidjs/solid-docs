A hydrating insert claimed an element the HTML parser moved out of its parent (invalid nesting across a component boundary: `<div>` in `<p>`, `<a>` in `<a>`, `<tr>` in `<table>`) (dev; client).

## Why it fires

Hydration claimed a server-rendered element that is not where the template put it: the nesting is invalid HTML, so the browser's parser rebuilt the tree.
A `<div>` closes an open `<p>`, an `<a>` closes an open `<a>`, a `<tr>` directly in a `<table>` gets a `<tbody>` the parser adds.
The compiler rejects this inside one template, so it nearly always spans a component boundary (`<P>{props.children}</P>` given a `<div>`, a `<For>` of row components inside `<table>`).
The page differs from a client render and the insert cannot update the moved node.
Warned once per parent, in dev only; the message names the parent, the child and where the parser put it.

## How to fix it

Fix: change the outer element (a `<div>` for a `<p>` that holds blocks, a `<span>` for an `<a>` that holds a link), move the inner element out, or write the wrapper the parser expects — `<table><tbody><For …>{r => <Row />}</For></tbody></table>`.
A `<form>` inside a `<form>` is dropped by the parser instead; the hydration key miss names it.
