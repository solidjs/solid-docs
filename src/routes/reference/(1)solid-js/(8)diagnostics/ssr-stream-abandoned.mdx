Response stream cancelled or sink failed with fragments pending (observe + dev).

## What you saw

- **Kind:** `ssr`
- **Severity:** `warn` (code that works but is structurally wrong or expensive)

The console report opens with `[SSR_STREAM_ABANDONED]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "SSR_STREAM_ABANDONED"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

The client went away (`data.reason: "consumer"`), the sink failed (`"sink"`), or the request's `signal` aborted (`"signal"` — `renderToStream`'s `signal` option, how a frame-stream response learns its reader is gone) while `data.pendingFragments` were still rendering; the render was torn down.
Not an app bug.

:::note[Server rendering]
The server runtime reports on the same channel, with the same `in <App> › <Page>` line.
Two groups.
**Findings** ([`SSR_RENDER_ERROR_CONTAINED`](/reference/solid-js/diagnostics/ssr-render-error-contained), [`SSR_SUBTREE_ABANDONED`](/reference/solid-js/diagnostics/ssr-subtree-abandoned), `SSR_STREAM_ABANDONED`, [`LATE_HEADER_WRITE`](/reference/solid-js/diagnostics/late-header-write), [`DYNAMIC_ASYNC_COMPONENT`](/reference/solid-js/diagnostics/dynamic-async-component), [`SERVER_ERROR_SANITIZED`](/reference/solid-js/diagnostics/server-error-sanitized), [`FRAME_MARKER_CORRUPTED`](/reference/solid-js/diagnostics/frame-marker-corrupted)) are facts about a render that exist in observe builds too — an APM sees them in production; in dev they print.
**Checks** (the rest, [`SSR_BOUNDARY_WATERFALL`](/reference/solid-js/diagnostics/ssr-boundary-waterfall) and [`SSR_CLIENT_CONTENT_MASKED`](/reference/solid-js/diagnostics/ssr-client-content-masked) included) are dev-only guidance.
A captured artifact from a server render carries both.
:::

## How to fix it

At volume it is the cost of renders nobody waited for: make the pending data faster or move it behind navigation.

## In tests

`captureArtifact` from `@solidjs/diagnostics` runs a scenario with the diagnostics channel open and returns the events it saw.
`expectNoDiagnostics(artifact)` fails while `SSR_STREAM_ABANDONED` is among them, with the events as evidence; after the fix, the code is gone from `artifact.diagnostics`.
[Check for regressions in tests](/guides/debugging-reactivity#check-for-regressions-in-tests) shows the loop and the Vitest matcher form.
