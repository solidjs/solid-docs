Client-only content in a `<Loading>` surfaced only after a server wait; the server's work was discarded (dev).

## What you saw

- **Kind:** `ssr`
- **Severity:** `warn` (code that works but is structurally wrong or expensive)

The console report opens with `[SSR_CLIENT_CONTENT_MASKED]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "SSR_CLIENT_CONTENT_MASKED"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

A `<Loading>` boundary's content turned out to be client-only (a `ssrSource: "client"` read) but only after `data.passes - 1` real server waits: an async read on an earlier pass masked it.
The server did the work (`data.durationMs`), streamed the fallback, then handed the whole subtree to the client anyway — the work was discarded and the user saw the fallback for the wait, then a client render.

:::note[Server rendering]
The server runtime reports on the same channel, with the same `in <App> › <Page>` line.
Two groups.
**Findings** ([`SSR_RENDER_ERROR_CONTAINED`](/reference/solid-js/diagnostics/ssr-render-error-contained), [`SSR_SUBTREE_ABANDONED`](/reference/solid-js/diagnostics/ssr-subtree-abandoned), [`SSR_STREAM_ABANDONED`](/reference/solid-js/diagnostics/ssr-stream-abandoned), [`LATE_HEADER_WRITE`](/reference/solid-js/diagnostics/late-header-write), [`DYNAMIC_ASYNC_COMPONENT`](/reference/solid-js/diagnostics/dynamic-async-component), [`ASYNC_MEMO_ELEMENT`](/reference/solid-js/diagnostics/async-memo-element), [`SERVER_ERROR_SANITIZED`](/reference/solid-js/diagnostics/server-error-sanitized), [`FRAME_MARKER_CORRUPTED`](/reference/solid-js/diagnostics/frame-marker-corrupted)) are facts about a render that exist in observe builds too — an APM sees them in production; in dev they print.
**Checks** (the rest, [`SSR_BOUNDARY_WATERFALL`](/reference/solid-js/diagnostics/ssr-boundary-waterfall) and `SSR_CLIENT_CONTENT_MASKED` included) are dev-only guidance.
A captured artifact from a server render carries both.
:::

## How to fix it

Give the client-only read its own `<Loading>` so it hands off with the shell while the async data streams, or read it before the async data so the boundary hands off on its first pass (no finding for that case).

## In tests

`captureArtifact` from `@solidjs/diagnostics` runs a scenario with the diagnostics channel open and returns the events it saw.
`expectNoDiagnostics(artifact)` fails while `SSR_CLIENT_CONTENT_MASKED` is among them, with the events as evidence; after the fix, the code is gone from `artifact.diagnostics`.
