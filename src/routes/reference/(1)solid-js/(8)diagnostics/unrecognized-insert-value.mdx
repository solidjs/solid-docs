Value at an insert position the renderer cannot render; skipped (dev; server and client).

## What you saw

- **Kind:** `render`
- **Severity:** `warn` (code that works but is structurally wrong or expensive)

The console report opens with `[UNRECOGNIZED_INSERT_VALUE]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "UNRECOGNIZED_INSERT_VALUE"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

A value the renderer cannot render (a plain object, a symbol — `data.type`) sat at an insert position and was skipped, on either platform.

:::note[Server rendering]
The server runtime reports on the same channel, with the same `in <App> › <Page>` line.
Two groups.
**Findings** ([`SSR_RENDER_ERROR_CONTAINED`](/reference/solid-js/diagnostics/ssr-render-error-contained), [`SSR_SUBTREE_ABANDONED`](/reference/solid-js/diagnostics/ssr-subtree-abandoned), [`SSR_STREAM_ABANDONED`](/reference/solid-js/diagnostics/ssr-stream-abandoned), [`LATE_HEADER_WRITE`](/reference/solid-js/diagnostics/late-header-write), [`DYNAMIC_ASYNC_COMPONENT`](/reference/solid-js/diagnostics/dynamic-async-component), [`ASYNC_MEMO_ELEMENT`](/reference/solid-js/diagnostics/async-memo-element), [`SERVER_ERROR_SANITIZED`](/reference/solid-js/diagnostics/server-error-sanitized), [`FRAME_MARKER_CORRUPTED`](/reference/solid-js/diagnostics/frame-marker-corrupted)) are facts about a render that exist in observe builds too — an APM sees them in production; in dev they print.
**Checks** (the rest, [`SSR_BOUNDARY_WATERFALL`](/reference/solid-js/diagnostics/ssr-boundary-waterfall) and [`SSR_CLIENT_CONTENT_MASKED`](/reference/solid-js/diagnostics/ssr-client-content-masked) included) are dev-only guidance.
A captured artifact from a server render carries both.
:::

## How to fix it

Usually a component function inserted where its call was meant, or an object where one of its properties was.

## In tests

`captureArtifact` from `@solidjs/diagnostics` runs a scenario with the diagnostics channel open and returns the events it saw.
`expectNoDiagnostics(artifact)` fails while `UNRECOGNIZED_INSERT_VALUE` is among them, with the events as evidence; after the fix, the code is gone from `artifact.diagnostics`.
[Check for regressions in tests](/guides/debugging-reactivity#check-for-regressions-in-tests) shows the loop and the Vitest matcher form.
