`runWithOwner` with disposed owner.

## What you saw

- **Kind:** `owner`
- **Severity:** `warn` (code that works but is structurally wrong or expensive)

The console report opens with `[RUN_WITH_DISPOSED_OWNER]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "RUN_WITH_DISPOSED_OWNER"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

`runWithOwner` received an owner that was already disposed; anything created inside leaks.

## How to fix it

This usually means a stale owner captured across an await or stored past its lifetime — re-capture the owner at call time or guard with `isDisposed()`.

## In tests

`captureArtifact` from `@solidjs/diagnostics` runs a scenario with the diagnostics channel open and returns the events it saw.
`expectNoDiagnostics(artifact)` fails while `RUN_WITH_DISPOSED_OWNER` is among them, with the events as evidence; after the fix, the code is gone from `artifact.diagnostics`.
