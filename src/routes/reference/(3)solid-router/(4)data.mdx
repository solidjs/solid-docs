## Import

```ts
import {
	formAction,
	liveQuery,
	query,
	revalidate,
	useSubmissions,
} from "@solidjs/router";
```

## `query`

```ts
function query<T extends (...args: any[]) => any>(
	fn: T,
	name: string
): CachedFunction<T>;
```

Returns a cached function with key helpers:

```ts
type CachedFunction<T extends (...args: any[]) => any> = ((
	...args: Parameters<T>
) => ReturnType<T>) & {
	key: string;
	keyFor(...args: Parameters<T>): string;
};
```

```ts
const getUser = query(fetchUser, "users");

getUser.key;
getUser.keyFor("42");
```

Cache keys combine `name` with a stable JSON serialization of the arguments.
Plain object keys are sorted during serialization.

When `fn` is a server function without a declared method, `query` wraps it as a GET server function.

### Cache methods

```ts
query.get(key: string): any;
query.set<T>(key: string, value: T): void;
query.delete(key: string): boolean;
query.clear(): void;
```

`query.get` returns the settled cached value.
`query.get` throws when no entry exists.
`query.set` does not accept a promise value.

## `liveQuery`

```ts
function liveQuery<T extends (...args: any) => any>(
	fn: T,
	name: string
): LiveFunction<T>;
```

Declares a keyed query over an async-iterable producer.
Each value the producer yields is the next value of the query.
The producer must yield the current state each time it is invoked.

```ts
type LiveFunction<T extends (...args: any) => any> = ((
	...args: Parameters<T>
) => AsyncIterable<Value>) & {
	key: string;
	keyFor(...args: Parameters<T>): string;
	status(...args: Parameters<T>): LiveQueryStatus;
};

type LiveQueryStatus =
	"idle" | "connecting" | "connected" | "reconnecting" | "closed";
```

`Value` is the producer's yielded type, or its resolved return type when it does not return an iterable.

```ts
const roomMessages = liveQuery(getMessages, "messages");

const messages = createMemo(() => roomMessages(props.room));
```

- Keys combine `name` with the arguments, as `query` keys do.
- Consumers of one key share one connection. A late consumer receives the latest value first. The connection closes when the last consumer leaves.
- A stream that has delivered a value and then fails with a network error or a 5xx status reconnects with exponential backoff. The latest value stays available meanwhile.
- A failure before the first value, or a 4xx status, ends the channel and throws to consumers.
- When `fn` is a server function without a declared method, `liveQuery` wraps it as a GET server function.
- A call under preload intent connects the channel and holds it open for 5 seconds.
- Mutations do not revalidate live keys. `revalidate(key)` with `force` reconnects the matching channels.
- On the server, the document renders the first value. Hydration adopts it and reconnects.
- `status(...args)` is a reactive read of the channel's connection state.

## `revalidate`

```ts
function revalidate(key?: string | string[] | void, force?: boolean): void;
```

Retriggers live matching cache entries.
Keys match by prefix.
Omit `key` to match all entries.
`force` defaults to `true` and marks the matched entries stale before retriggering them.

## `formAction`

```ts
function formAction<T extends any[], U = void>(
	fn: (...args: T) => Promise<U>,
	name?: string
): FormAction<T, U>;

function formAction<T extends any[], U = void>(
	fn: (...args: T) => Promise<U>,
	options?: { name?: string }
): FormAction<T, U>;
```

```ts
type FormAction<T extends any[], U, V = T> = ((
	...variables: T
) => Promise<NarrowResponse<U>>) & {
	url: string;
	with<A extends any[], B extends any[]>(...args: A): FormAction<B, U, V>;
	onSubmit(
		hook: (...args: V extends any[] ? V : T) => void
	): FormAction<T, U, V>;
	onSettled(
		hook: (
			submission: Submission<V extends any[] ? V : T, NarrowResponse<U>>
		) => void
	): FormAction<T, U, V>;
};
```

Form actions whose arguments are `[FormData]`, `[URLSearchParams]`, or `[]` implement Solid's serializable JSX attribute value.
Client form actions need a stable name when rendered on the server.
Server functions supply their own URL.

### Form use

```tsx
<form action={save} method="post">
	<button>Save</button>
</form>
```

Only POST forms are accepted by delegated form action handling.
The form has `aria-busy="true"` from its delegated submission until the form action's held update commits.
Busy state is keyed by the form's `action` URL, so every form posting to that URL shows it.
The router does not overwrite or remove an `aria-busy` value the author set.

### `with`

Binds leading arguments and returns a form action for the remaining arguments.
The bound arguments are represented in the form action's URL.

### `onSubmit`

Registers a callback that runs before the mutation call.
Registration under an owner is removed when the owner is disposed.

### `onSettled`

Registers a callback for every completed invocation.
The callback receives a `Submission`, including for void, redirect, and metadata-only outcomes.
Callbacks run when the form action's held update commits, after any revalidation or redirect it holds has rendered.
The submission record appears in `useSubmissions` at the same point.

## Server function responses

While a router is mounted and `singleFlight` is not `false`, the router applies the response of every non-`GET` server-function call, whether or not a form action made it.
It applies `X-Revalidate` keys, `redirect()`, `reload()`, and single-flight data.
A `POST` call that declares no `revalidate` keys revalidates every query.
Functions wrapped by `query` or declared with `GET()` are reads and are exempt.
`revalidate: ""` declares no keys, the same as `revalidate: []`.

## Deprecated

### `action`

```ts
const action: typeof formAction;
type Action<T extends any[], U, V = T> = FormAction<T, U, V>;
```

Deprecated alias of `formAction`, and of the `FormAction` type.
Logs a development warning on first use.
Unrelated to the `action` exported by `solid-js`.

### `useAction`

```ts
function useAction<T extends any[], U, V>(
	action: FormAction<T, U, V>
): (...args: T) => Promise<NarrowResponse<U>>;
```

Deprecated, with no replacement.
Logs a development warning.
Call the server function directly, or a core `action` from `solid-js` around it.
Binds direct form action invocation to the current router context.
The returned promise resolves when the action body finishes, which can be before the action settles and `onSettled` runs.

## `useSubmissions`

```ts
function useSubmissions<T extends any[], U, V>(
	action: FormAction<T, U, V>,
	filter?: (input: V) => boolean
): Submission<V, NarrowResponse<U>>[];
```

Returns a reactive array proxy of settled records for the form action.
The router retains only records with a result or error.

```ts
type Submission<T, U> = {
	readonly input: T;
	readonly result?: U;
	readonly error: any;
	readonly url: string;
	clear(): void;
	retry(): void;
};
```
