Reading pending async outside tracking scope.

## What you saw

- **Kind:** `async`
- **Severity:** `error` (broken behavior)

The console report opens with `[PENDING_ASYNC_UNTRACKED_READ]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "PENDING_ASYNC_UNTRACKED_READ"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

The same shape as [`STRICT_READ_UNTRACKED`](/reference/solid-js/diagnostics/strict-read-untracked), but the value was a pending async computation, so there is nothing to read yet at all.

## How to fix it

Async values must be read where tracking can suspend and resume: JSX, a memo, or an effect's compute function.

## In tests

`captureArtifact` from `@solidjs/diagnostics` runs a scenario with the diagnostics channel open and returns the events it saw.
`expectNoDiagnostics(artifact)` fails while `PENDING_ASYNC_UNTRACKED_READ` is among them, with the events as evidence; after the fix, the code is gone from `artifact.diagnostics`.
