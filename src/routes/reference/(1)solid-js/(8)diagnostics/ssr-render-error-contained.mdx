Server render error routed by a boundary: `data.handling` fallback / client / failed (observe + dev).

## What you saw

- **Kind:** `ssr`
- **Severity:** `error` (broken behavior)

The console report opens with `[SSR_RENDER_ERROR_CONTAINED]` and the message, then an `in` line naming the owners that enclose the subject, root first, and an `at` line with the source location when the code was compiled with one.
In a captured artifact the same finding is an event with `code: "SSR_RENDER_ERROR_CONTAINED"`, `ownerPath`, and `loc`.
[Diagnostics](/reference/solid-js/diagnostics#read-a-report) explains each line.

## Why it fires

A component threw during a server render and a boundary routed the error; `data.handling` says how.
`fallback` — an `<Errored>` rendered its fallback (the response was a 200 showing the fallback; if this fires on every request the fallback is the page).
`client` — the enclosing `<Loading>` fragment rejected and the client re-rendered the subtree after hydration (the user paid a client render and a flash).
`failed` — nothing contained it and the request failed.

:::note[Server rendering]
The server runtime reports on the same channel, with the same `in <App> › <Page>` line.
Two groups.
**Findings** (`SSR_RENDER_ERROR_CONTAINED`, [`SSR_SUBTREE_ABANDONED`](/reference/solid-js/diagnostics/ssr-subtree-abandoned), [`SSR_STREAM_ABANDONED`](/reference/solid-js/diagnostics/ssr-stream-abandoned), [`LATE_HEADER_WRITE`](/reference/solid-js/diagnostics/late-header-write), [`DYNAMIC_ASYNC_COMPONENT`](/reference/solid-js/diagnostics/dynamic-async-component), [`ASYNC_MEMO_ELEMENT`](/reference/solid-js/diagnostics/async-memo-element), [`SERVER_ERROR_SANITIZED`](/reference/solid-js/diagnostics/server-error-sanitized), [`FRAME_MARKER_CORRUPTED`](/reference/solid-js/diagnostics/frame-marker-corrupted)) are facts about a render that exist in observe builds too — an APM sees them in production; in dev they print.
**Checks** (the rest, [`SSR_BOUNDARY_WATERFALL`](/reference/solid-js/diagnostics/ssr-boundary-waterfall) and [`SSR_CLIENT_CONTENT_MASKED`](/reference/solid-js/diagnostics/ssr-client-content-masked) included) are dev-only guidance.
A captured artifact from a server render carries both.
:::

## How to fix it

In every case the repair is the error in `data.error`, in the component `ownerPath` names; then consider whether an `<Errored>` closer to the throw would contain it more narrowly.
