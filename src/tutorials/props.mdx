# Reactive props and defaults

Props carry reactive reads into a component. Read `props.name` in JSX or in a derivation to keep it connected. Copying it into a plain local variable during setup freezes that read.

Use a nullish fallback when a missing or `undefined` value should receive a default:

```jsx
<h3>
  {props.greeting ?? 'Hi'} {props.name ?? 'John'}
</h3>
```

`merge(defaults, props)` creates a reactive combined view, but `undefined` is a real override in Solid 2. A prop explicitly set to `undefined` will not automatically pick the earlier value. The solved code uses `??` for the optional name and `merge` for the greeting.

**Try it:** add defaults in `greeting.jsx`. The first two greetings should use missing defaults; the third should change when **Set Name** is clicked.
